## 背景与复现

- `extension/content.js` 的 `isBusy()` 主要依赖 Stop / 停止生成按钮。ChatGPT 在 thinking、工具调用、渲染切换或连续输出之间，该按钮可能短暂消失，导致页面**仍在执行当前 Web Turn** 时被误判为空闲。
- `extension/background.js` 收到新消息后按角色查找匹配标签页，直接请求内容脚本自动输入并发送收件提醒；这可能在原工作中途插入新 User Turn，打断 Agent。本来 Web Agent 可能在自己结束前查看 `web_mail(inbox)` 并消费这些新信，无须额外注入。
- 不应仅凭单个按钮消失、输入框为空、网络不活跃或页面焦点状态，就认定当前回复已结束。页面 DOM 随版本变化，应以真实浏览器核验，不猜 selector。

## 验收条件

1. **正在推理、调用工具、连续生成中**：即使 Stop 按钮暂时不见，也不自动插入、点击 Send 或中断当前 Turn。
2. **自然收尾**：Web Agent 最多一次有界查信；处理并 ACK 的消息不会被再次提醒；只报告/处理真实新消息，不要求每轮无限清空收件箱。
3. **确实空闲且未 ACK**：消息最终可按既有机制提交**一次**；草稿、附件与用户输入始终不受损。
4. **状态准确**：`pending → submitted → done` 仅由真实 UI 提交、真实 MCP ACK 驱动，遇到失败/竞态不会错标 ACK 或重复派工。
